Dialog 对话框

A panel that asks the reader something, written as a <dialog>. It is shown the way a dialog is shown without JavaScript — open in the markup — and it is closed the way the browser closes one: the close button submits the form around it, and the form's method is dialog.

dialog, form, h2, div, button feedback since 1.1.0

The close button is the browser's own, not a handler of the library's. A <form method="dialog"> inside the dialog turns a submit into a close, so the button needs no listener and the component needs no JavaScript at all — which also means the button keeps working when the host opens the panel with showModal(). What the library does not paint is the mask: the backdrop of a modal dialog belongs to the browser, and the static form has none, because there is no role in the contract for a scrim and a second translucent layer over the page is a colour no role names.

Examples

Basic · 基础用法
A panel with a title, a body and two actions. The close button is a submit button inside a form whose method is dialog, so it closes the panel the way the browser closes one — and the cross is drawn from two borders, so it needs no icon font.

Archive this deployment?

Build 214 is still running on three nodes. Archiving it stops the queue and keeps the log.

 
<dialog open class="um-dialog" aria-labelledby="um-dialog-title">
  <form method="dialog" class="um-dialog__form">
    <div class="um-dialog__header">
      <h2 class="um-dialog__title" id="um-dialog-title">Archive this deployment?</h2>
      <button class="um-dialog__close" type="submit" aria-label="Close"></button>
    </div>
    <div class="um-dialog__body">
      <p>Build 214 is still running on three nodes. Archiving it stops the queue and keeps the log.</p>
    </div>
    <div class="um-dialog__footer">
      <button type="button">Cancel</button>
      <button class="um-dialog__action" type="button">Archive</button>
    </div>
  </form>
</dialog>
Centred · 居中
The centred variant puts the title and the actions in the middle of their rows instead of at the two ends. The close button stays in the corner, because that is where a corner is.

Props

NameTypeDefaultDescription
titlestring—The heading of the panel.
alignenum = start | centerstartWhere the title and the actions sit. The start alignment is the base class on its own; the centred one adds um-dialog--center.
sizeenum = sm | md | lgmdHow wide the panel is. The width is a measure of the panel's own type, so the panel grows with the mood's text instead of holding a fixed pixel width.
centerbooleanfalseWhether the title and the actions are centred. This is Element Plus's name for the `align` prop's centred value; either one of them centres the panel.
align-centerbooleanfalseWhether the panel sits in the middle of the screen rather than in the flow of the page. It adds um-dialog--align-center.
fullscreenbooleanfalseWhether the panel takes the whole screen. It adds um-dialog--fullscreen.
modalbooleanfalseWhether the panel is opened as the browser's own modal dialog, in the top layer and with the backdrop the browser paints for it. The library paints no mask of its own.
model-valueboolean—Whether the panel is open. The binding wins over the static form, which is the open one.
show-closebooleantrueWhether the panel carries a close button in its header.

Slots

NameDescription
titleWhat is inside the heading.
headerWhat is in the header, in place of the title. The close button stays: replacing the header removes the title, not the way out.
defaultThe body of the panel.
footerThe actions in the footer. This is Element Plus's name for the `actions` slot; either one of them fills the footer.
actionsThe actions in the footer.

Events

NameDescription
closeFires when the panel closes. The close is the browser's own: the close button submits the form around the panel, and the browser tells the wrapper the dialog is done.
openFires when the panel opens. The panel is open in the markup, so the event fires when it reaches the page and again whenever the host opens it after that.

Accessibility

Role: dialog

Keyboard: Tab Enter Escape

The panel is a <dialog>, so the browser knows it is a dialog, and the dialog points at its title with aria-labelledby so the reader hears what the panel is about instead of a bare "dialog". The close button is a real button inside a form whose method is dialog: submitting it is the browser's own way of closing a dialog, so the library installs no listener and handles no key. A static dialog is not modal — it does not take the focus, it does not make the page behind it inert, and Escape does not close it, because all three of those belong to showModal(), and that is JavaScript. Put the panel in the flow where the reader expects it, and give the host a way to open it.
