Timeline 时间线

What happened, in order. An ordered list with a rail down one side and a dot at each entry, so the order is in the structure and not only in the picture.

ol, li, span, div data since 1.1.0

The tone modifier hangs off the item rather than off the base class, so the manifest's modifier prefix is `um-timeline__item--`: one timeline usually carries a success, a warning and a plain entry at once, and a tone on the whole list could only say one thing. The rail is positioned against the item, not against the text, so it stays under the dots when the text beside it wraps.

Examples

A timeline · 一条时间线
The rail is drawn by the tail and the dot by the node. The last entry has no rail below it.
  1. 28 November, 09:12 Build 214 started on node A.
  2. 28 November, 14:20 Three nodes reported the same result.
  3. 28 November, 16:05 The build was marked as passing.

Props

NameTypeDefaultDescription
variantenum = success | warning | danger—The tone of the entry. It is written on the item, not on the timeline.
timestampstring—When it happened. It is a time element inside the wrapper, so the machine-readable value and the written one travel together.

Slots

NameDescription
wrapperThe body of the entry: the timestamp and the text.

Accessibility

Role: list

The timeline is an ol, so the reader is told how many entries there are and can step through them. The node and the rail carry no information the text does not already carry: mark them aria-hidden, and the entry is read as one line of text.
