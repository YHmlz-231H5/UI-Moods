Virtualized Table 虚拟表格

A long table the browser is not asked to lay out in full. The rows far from the viewport are skipped and given a placeholder size, so the cost of the list is what is near it.

div data since 1.1.0

The rows are a grid of divs rather than a <table>, and that is what makes the skip possible: a browser will not skip the layout of a table row, because a row is sized by its table. Measured in Chrome 158 on a 200-row table, content-visibility: auto on the <tr> left the table at exactly the height it had without the rule — every row still at its own 30px — while the same rule on a grid of divs left 165 of the 200 rows at their placeholder size. Put on the <td>s it broke the table instead: the rows collapsed from 30px to 9px and the total height changed while the reader scrolled. The header and the rows share one column template, so the names travel with the cells whatever the column count is.

Accessibility

Role: grid

Keyboard: Tab Arrow keys Page Up Page Down Home End

The table is an ARIA grid of divs: role="grid" on the scrolling box, role="row" on each row and role="gridcell" on each cell, so a screen reader reads a row across and announces the column name with every cell — the same thing a real table does. It is a grid of divs rather than a real <table> for a measured reason: Chrome will not skip the layout of a table row, because a row is sized by its table, so content-visibility: auto on a <tr> changed nothing at all in a 200-row table, and on the <td>s it broke the row heights. The scrolling box is a real element with overflow on it and a tabindex, so it can be reached with Tab and scrolled with the arrow keys, the page keys and Home and End — the browser's own scrolling, not a script.
