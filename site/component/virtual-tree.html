Virtualized Tree 虚拟树

A tree so large that the browser is asked to lay out only the branches near the reader. Every branch is still a disclosure, so the browser opens and closes it and the state survives a reload.

div, details, summary data since 1.1.0

The skip happens on the branches themselves: each branch's children carry content-visibility: auto, so a branch far from the viewport costs a placeholder size instead of a layout. Skipping the level they sit in instead was measured and rejected: it reserves one branch's height for the whole level, so the list the reader can scroll comes to 2519px against a true 3680px and never catches up — 2906px after scrolling to the end. Skipping each child reserves its own height, so the level keeps its length: 3539px against the same 3680px, and 66 of the 72 branches were skipped. The placeholder is the label's own height, composed from the theme's gap rather than written as a number, so it is the same size as the branch it stands in for in every mood; the auto keyword in contain-intrinsic-size makes it the size the branch really had the last time it was laid out. The cost of that is the one every CSS-native virtualisation pays: the list is in the document, so the browser skips the layout and not the markup.

Accessibility

Role: group

Keyboard: Tab Enter Space

Every branch is a real <details> and every label is a real <summary>, so the browser announces each label as a disclosure button and says whether its branch is open. The keyboard is the browser's own: Tab reaches the labels, Enter or Space opens the branch. The arrow is drawn from borders, so it carries no text — the state is announced by the browser, not by the mark. The tree role is not used on purpose: it promises tree items and arrow-key navigation, and a tree of disclosures does not deliver either. The scrolling box is a real element with overflow on it and a tabindex, so it can be reached with Tab and scrolled with the arrow keys, the page keys and Home and End.
