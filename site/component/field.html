Field 表单项

The scaffolding around a control: a label, the control itself, and a line of text that says what to do next. It owns the spacing, so a form does not have to.

div form since 1.1.0

The field is a wrapper rather than a class you put on the control, because the control has to stay the element the platform knows about — a real input, a real select. The error modifier is the only state the field owns; the label and the message are muted roles, not a second theming system.

Examples

Layout · 布局
A label, a control and a message. The field owns the gaps between them, so nothing here needs a margin of its own.
The name other people will see. 
<div class="um-field">
  <label class="um-field__label" for="um-field-name">Name</label>
  <input class="um-input" id="um-field-name" type="text" placeholder="Type here" />
  <span class="um-field__message">The name other people will see.</span>
</div>
Error · 错误
The error modifier reaches into the control: the border of the input, textarea or select inside the field turns to the danger colour, and the message stops being muted. The message is text, so it takes the derived danger text colour rather than the raw danger fill.
Enter a valid email address. 
<div class="um-field um-field--error">
  <label class="um-field__label" for="um-field-email">Email</label>
  <input class="um-input" id="um-field-email" type="text" value="not-an-email" />
  <span class="um-field__message">Enter a valid email address.</span>
</div>

Accessibility

The field is a plain container; the accessibility work is done by the label and the control. Use a real <label for> that points at the control's id, and aria-describedby when the message carries something the user needs to hear. The library paints the error state but does not announce it — that is the host's job.
