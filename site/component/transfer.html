Transfer 穿梭框

Two lists side by side with a button between them: what is available on one side, what has been chosen on the other. The whole thing is a form, so the move is a submission.

form, input, button, ul data since 1.1.0

The move is a submission, not an animation. The buttons are real submit buttons that carry their direction in their value, and the ticked options are the form's own fields, so a host that receives the post can move them and write the two lists back. The library draws the two panels, the rows and the arrows; the arrows are shapes made of borders, so they take the button's colour and need no glyph of its own.

Props

NameTypeDefaultDescription
namestring—The name the ticked options are submitted under. It is the native name attribute, and the source and the target list use different names so the host can tell them apart.
valuestring—The value one option submits while it is ticked.
checkedbooleanfalseTicks one option. It is the native checked attribute, not a class.
disabledbooleanfalseMakes one option, or one of the move buttons, inert. It uses the real disabled attribute, so it leaves the tab order.
directionenum = horizontal | verticalhorizontalWhich way the two panels are laid out. The horizontal run is the base class on its own; the vertical run adds um-transfer--vertical.
sizeenum = sm | md | lgmdThe size of the names and of the move buttons.

Slots

NameDescription
sourceThe options of the panel on the left.
targetThe options of the panel on the right.
left-footerThe row under the list of the panel on the left.
right-footerThe row under the list of the panel on the right.

Events

NameDescription
changeFires when an option is ticked or unticked. It is the browser's own event on the input — the library installs no listener.
submitFires when the form is submitted, which is how a move happens: the buttons carry the direction in their value and the ticked items in the form's own fields.

Accessibility

Role: group

Keyboard: Tab Space Enter

Every option is a real <input type="checkbox"> inside a <label>, so ticking it is the browser's :checked and the value submits with the form. The two move buttons are real buttons, so they are in the tab order and can be pressed — but their arrows are drawn from borders, so each one needs an aria-label saying which way it moves. The move itself is a submission: the library has no JavaScript, so the host that receives the form does the moving and writes the two lists back.
