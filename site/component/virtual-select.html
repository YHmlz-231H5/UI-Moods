Virtual Select 虚拟列表选择器

A long list of choices that the browser only lays out near the viewport. The rows far away are skipped, and the browser is told how tall such a row is, so the scrollbar is right without every row being built.

div form since 1.1.0

The rows far from the viewport are not laid out: `content-visibility: auto` tells the browser to skip the work for them, and `contain-intrinsic-size` says how big a row that has never been looked at is. The row height is a length of the component's own and not a number of pixels, because a row's height follows the theme's type and the library's pixel allowlist has no row in it. The options are real radios inside labels, so the selection is a form value the host can read; the virtualisation is only about the painting, and nothing about the choice changes because of it.

Examples

Props

NameTypeDefaultDescription
valuestringAardvarkThe label of the option that is chosen. It is the radio's own value, so the choice is the browser's and not the library's.
model-valuestring—The bound value. It answers to `v-model` as well as to `value`, and the binding wins when it is there.
optionsstringAardvark,Albatross,Badger,Barracuda,Beetle,Bison,Butterfly,Capybara,Caribou,Chameleon,Cheetah,ChinchillaThe labels in the list, separated by commas. The wrapper draws one option per label; the markup writes the options out.
placeholderstringChoose a speciesThe text that names the list and stands in for a choice. It is the accessible name of the listbox, so the browser announces it when the reader reaches the list. The library has no field to write a selection into, so the placeholder is what the list is called.
heightstring12emThe height of the scroller. It is a length and not a number of pixels: how tall the window onto the list is belongs to the host's page.

Events

NameDescription
changeFires when an option is picked. It is the browser's own event on the radio — the library installs no listener.

Accessibility

Role: listbox

Keyboard: Tab Arrow keys Space

The list is a listbox and the rows are options, so the browser says what the list holds and which row is current. Underneath that, every option is a real radio inside a label, so the choice is in the tab order, the arrow keys move between the choices and the browser announces the picked one; the radio is kept out of sight with the same technique the switch uses, so it is still a control the keyboard can reach. Each radio names itself, because a row is a label and a label carries no text of its own.
