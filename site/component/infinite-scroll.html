Infinite Scroll 无限滚动

A feed the reader can scroll a long way through, and a sentinel at the end of it that says what comes next. The library cannot load anything: it provides the container, the skipped layout and the sentinel, and the host decides what to load.

div data since 1.1.0

The library cannot load anything, so the honest division of labour is this: the library provides the container, the skipped layout and the sentinel that says where the reader is, and the host decides what to load. The sentinel's state is a class the markup carries, so the host can change it without the library knowing anything about the data. The items are skipped the way the virtualized components skip their rows, which is the same effect an infinite scroll has in practice: the cost of the list is what is near the viewport. Measured in Chrome 158 on the forty-four items of the example, sixteen of them were skipped and twenty-eight were laid out, and the placeholder is the item's own content height, so the feed measures the same length with the virtualisation on as with it off.

NameTypeDefaultDescription

Role: group

Keyboard: Tab Arrow keys Page Up Page Down Home End

The sentinel carries role="status", so the moment it changes is announced: the words on it say whether more is coming, whether the last item has arrived or whether there is nothing more. The ring beside the words is a picture of waiting rather than a message, so it is marked aria-hidden and the caption carries the meaning. The scrolling box is a real element with overflow on it and a tabindex, so it can be reached with Tab and scrolled with the arrow keys, the page keys and Home and End — the browser's own scrolling, not a script. The library loads nothing: the host decides what to put in the feed, and this component only says where the reader has reached.
