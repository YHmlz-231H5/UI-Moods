Input Number 数字输入框

A field for a number, with a pair of buttons that step it up and down. The buttons are real buttons, so they are in the tab order and the browser announces them; the browser's own spin buttons are taken away so there is only one pair.

input, button, div form since 1.1.0

The browser's own spin buttons are removed and the custom pair takes their place, because two pairs on the same corner is one pair too many. The buttons draw their marks from CSS rather than shipping glyphs, which is why each one needs an aria-label: a drawn mark carries no text, and a button with no name is a button the reader cannot tell apart from its neighbour.

Examples

Basic · 基础用法
A number field with the pair of buttons on the right. Each button names itself, because its mark is drawn and carries no text.
<div class="um-input-number">
  <div class="um-input-number__wrapper">
    <input class="um-input-number__input" type="number" value="3" min="0" max="10" step="1" aria-label="Replicas" />
    <span class="um-input-number__controls">
      <button class="um-input-number__increase" type="button" aria-label="Increase"></button>
      <button class="um-input-number__decrease" type="button" aria-label="Decrease"></button>
    </span>
  </div>
</div>
Controls on the left · 按钮在左
The same field with the pair of buttons on the left. The markup is unchanged except for the modifier — the buttons move with `order`, so the tab order is the same.

Disabled · 禁用
A disabled field with disabled buttons. They leave the tab order, and the number stays on screen so the reader can still read it.
<div class="um-input-number">
  <div class="um-input-number__wrapper">
    <input class="um-input-number__input" type="number" value="8" min="0" max="10" disabled aria-label="Replicas held back" />
    <span class="um-input-number__controls">
      <button class="um-input-number__increase" type="button" disabled aria-label="Increase">+</button>
      <button class="um-input-number__decrease" type="button" disabled aria-label="Decrease">−</button>
    </span>
  </div>
</div>

Props

NameTypeDefaultDescription
valuenumber—The number in the field. It is the input's own value, not a class — a class cannot carry a number.
minnumber—The smallest number the field accepts. It is the input's own min attribute, so the browser enforces it.
maxnumber—The largest number the field accepts. It is the input's own max attribute.
stepnumber1How much one press of a button changes the value. It is the input's own step attribute, and the browser's arrow keys use it too.
controls-positionenum = right | leftrightWhich side of the field the pair of buttons sits on. The right position is the base class on its own; the left position adds um-input-number--left.
disabledbooleanfalseMakes the field and both buttons inert. It uses the real disabled attribute, so they leave the tab order.

Events

NameDescription
changeFires when the value changes. It is the browser's own event on the input — the library installs no listener, and the buttons do not change the value either.

Accessibility

Role: spinbutton

Keyboard: Tab ArrowUp ArrowDown

The field is a real <input type="number">, so the browser validates it, the arrow keys change it and a screen reader announces it as a spin button. The two buttons are real buttons, so they are in the tab order and can be pressed — but they draw their marks from CSS, so they carry no text of their own and each needs an aria-label saying which way it goes. The focus ring is on the field and on each button separately, because one ring around the whole box would say the wrong thing about what is focused.
