Affix 固钉

A bar that stays where the reader put it while the page scrolls past. The bar is held with position: sticky, so the browser keeps it in the flow and pins it to the edge of the scrollport — no scroll listener, no measuring, no JavaScript.

div basic since 1.1.0

The offset is a CSS variable rather than a prop, because it is a length the host knows and the library does not: write --um-affix-offset on the affix (12px, 4rem, anything) and the bar leaves that much room between itself and the edge it sticks to. It stays a variable rather than a class because every length is a length — a scale of offset classes would be a scale of magic numbers wearing a class name.

Examples

Pinned to the top · 固定在顶部
A filter bar that holds the top edge of the viewport while the page scrolls under it. The space the bar takes stays reserved, because a sticky element is still in the flow — nothing jumps when the bar pins.
Only failed builds 
<div class="um-affix">
  <div class="um-affix__bar">
    <span>Only failed builds</span>
  </div>
</div>
Pinned to the bottom · 固定在底部
The bottom variant sticks to the lower edge of the viewport, which is where a progress strip belongs. The rule moves to the top of the bar, because that is the edge the bar is attached to.
3 of 214 builds are running 
<div class="um-affix um-affix--bottom">
  <div class="um-affix__bar">
    <span>3 of 214 builds are running</span>
  </div>
</div>

Accessibility

Keyboard: Tab

The affix is a plain container and carries no role: it is a place on the page that happens to stay put, not a landmark. What is inside the bar is ordinary focusable content, and the sticky position does not change where it sits in the tab order. The bar carries a surface of its own because it can cover the page behind it, and a bar that covers content without a surface of its own reads as a hole in the page.
