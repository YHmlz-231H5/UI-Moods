How we cut dashboard build time from three days to forty minutes

IP Ivan Petrov · 12 March 2026

Every Northwind dashboard used to be hand-built: a warehouse query, a spreadsheet export and a slide deck that was stale within a week. We moved the definitions into a semantic layer, and the reporting team now ships from templates instead of queries.

sync-revenue.tsTypeScript · 38 lines
// Pull settled invoices and upsert them into the daily table
import { createClient } from '@northwind/sdk'

const client = createClient({ token: process.env.NW_TOKEN })

export async function syncRevenue(warehouse: string) {
  const since = lastRun.get(warehouse) ?? '30d'
  const rows = await client.query<string>(warehouse, since)

  for (const row of rows) {
    await db.upsert('revenue_daily', row)
  }
  lastRun.set(warehouse, new Date())
  return rows.length
}

FAQ
How does Beacon bill for event volume?

We count billable events after sampling, so server-side heartbeats and debug traffic never reach your invoice. Your dashboard shows the running count for the current cycle and the exact rate applied on the next invoice.

Can we keep raw events in our own cloud account?

Yes. The collector writes to your own bucket first, and Beacon only stores the aggregated rows it queries. Point the collector at an S3, GCS or Azure target and switch on the warehouse-sync flag in your workspace settings.

What happens when we cross the event quota?

We never drop data and we never surprise you with a bill. At 80% of quota the workspace owner gets an email, at 100% collection continues in low-detail mode and dashboards keep working on the aggregates we already have.

Do you offer a free trial for Enterprise?

Enterprise pilots run for 30 days with the full feature set and a named engineer attached. There is no card on file and no automatic conversion at the end of the pilot.

Can we self-host the Beacon collector?

The collector ships as a signed container and a static binary, both published with checksums. It runs on your edge fleet with no outbound dependency beyond the ingest endpoint.

How do you handle GDPR deletion requests?

Beacon stores pseudonymous identifiers only. A deletion request removes every row for that subject within 24 hours across primary storage, backups and warehouse exports, and the workspace keeps an audit record of the request.

Still need help?

Our support engineers answer within four business hours on every plan, including the free tier. Most questions are resolved in the first reply.

Docs · Getting started · Quickstart

Send your first event

Beacon receives events over a single HTTP endpoint. Everything you need to ship a working integration is one request, one JSON body and one identifier that ties a person to their history.

Note
Events are sampled after ingestion. The raw payload is written to your bucket first, so nothing is lost even when the workspace applies sampling for reporting.

The event envelope

Every event carries a name, a timestamp and a user. Properties are free-form and are queryable within 90 days on every plan.

JSONPOST /v1/events
{
  "event": "checkout_completed",
  "user": { "id": "usr_8841" },
  "properties": {
    "plan": "pro",
    "amount_cents": 7900,
    "currency": "EUR"
  },
  "occurred_at": "2026-11-10T09:41:22Z"
}

Required properties

Only two fields are mandatory. Everything else has a sensible default so you can ship before the schema is settled.

FieldTypeRequiredNotes
eventstringYesLowercase, dots allowed
user.idstringYesPseudonymous, never an email
occurred_attimestampNoDefaults to receipt time
propertiesobjectNoUp to 64 keys per event

Verify from the console

Open the Events tab and watch the first payload arrive. If it does not show up within 30 seconds, check the workspace key and the source allow-list.
