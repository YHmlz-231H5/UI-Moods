# Acceptance Checklist — Schema Semantics

Reference: `UI-Moods-前置规划-v0.2.html` §6.3 + Cursor reviews R01/R02.
Machine-readable contract for `tools/validate.mjs`.

## 1. Item types

| `type` | Required fields | Meaning |
| --- | --- | --- |
| `value` | `assert.path` + `assert.eq` | Resolve `path` in `tokens.json`; must strictly equal `eq`. |
| `token-only` | `scope` | No literals outside the token source for the given scope (see §2). |
| `contrast` | `foreground`, `background`, `minRatio` | WCAG contrast ratio of resolved colors must be ≥ `minRatio`. |
| `subjective` | — (`required: false` by default) | Human judgment; agents state their trade-off in one sentence. |

## 2. `token-only` semantics

### v1 wiring table

Only two scopes actually drive a scan in v1; the remaining enum values are
kept for forward compatibility and produce a **warning** (not an error) when
used:

| checklist `token-only` scope | validate's actual behavior in v1 |
| --- | --- |
| `components` | unconditional `checkComponents` run (only when `tokens.components` exists): leaves must be token refs or the keyword whitelist |
| `colors` | unconditional specimen color-literal scan (specimen body, excluding `style#mood-tokens`) |
| `radii` / `shadows` / `spacing` / `borders` / `effects` / `typography` / `motion` | **not wired to a dedicated scan**; the global magic-number scan is independent of checklist items — a `scope: radii` item does not turn on radius-literal checking |

### `scope: components` (semantic layer inside `tokens.json`)

Leaf values are legal **only** if:

- `{group.key}` reference that resolves in the same tokens file, or
- a CSS keyword whitelist entry: `transparent` | `none` | `currentColor` |
  `inherit` | `0` (string or numeric zero).

Anything else (a color literal like `#0b0b18`, a size like `12px`) is an
error. To allow new structural values, extend the whitelist with
justification.

### `scope: colors` (specimen source)

- Literals inside the `style#mood-tokens` block are considered "from tokens"
  and are **not** errors (that block is generated by `build-specimen`).
- Everywhere else in the specimen (other styles, inline styles), color values
  must be `var(--mood-colors-*)` references or whitelist keywords
  (`transparent` | `currentColor` | `inherit` | `none`).

## 3. Contrast strategy

- Parse hex (`#rgb` / `#rrggbb`) and `rgb()/rgba()`.
- Composite translucent colors before computing the ratio:
  - if the foreground has alpha, composite it over the background color;
  - if the background has alpha, composite it over `colors.bg` when that
    resolves to a parseable color; otherwise over opaque white.
- Compute WCAG relative luminance and ratio; fail if ratio < `minRatio`.
- Known limits: nested multi-layer translucency and backdrop gradients are
  not modeled; prefer opaque `foreground`/`background` pairs for contrast
  assertions.

## 4. Magic-number scan (specimen, excluding `style#mood-tokens`)

Scanned categories and allowlists live in `docs/css-var-mapping.md` §5:
`font-size`, `letter-spacing`, `opacity`, pixel metrics, color literals.
Off-list values are errors; adding a value requires updating §5 first.

Known scan gaps (accepted for v1, will harden later):

- Color functions beyond `hex` / `rgb(a)` are **errors** when found in the
  specimen body (`hsl` / `hsla` / `oklch` / `lab` / `lch` / `color()`).
- Unitless values other than `opacity` are not scanned.

## 5. Report format

`ui-moods validate` prints one line per mood:

```
moods/<id>: PASS | FAIL (N errors)
```

Errors are listed with a short path, e.g.
`components.button.primary.fg: literal "#0b0b18" not in keyword whitelist`.
Exit code is `0` when every recorded mood passes, `1` otherwise.
